# 抖音是否调用 GPU —— 实测报告

设备：OESP（Amlogic S922X / G12B）· 容器 androidemu-android（redroid 12 arm64）· 2026-10-04

## 结论先说

**你的直觉对了一半：抖音确实一直在调用 GPU，但调用的是「3D 渲染」，不是「视频硬解」。**

而 CPU 突然变高，原因正是**硬解失效了**——VDEC 固件现在处于卡死状态，抖音拿不到硬解，回退到自己打包的软解库在 CPU 上硬算。

## 实测数据

| 指标 | 空闲 | 抖音运行中 | 判读 |
|---|---|---|---|
| `/dev/dri/renderD128` 打开数（抖音进程 fd） | — | **6 个** | GPU 3D 渲染在用（Mali-G52 / Panfrost） |
| `/dev/video0` 打开数（抖音进程 fd） | — | **0 个** | 硬件解码器未被调用 |
| panfrost-job 中断（GPU 干活计数） | 0.25 /s | **20 ~ 26 /s** | GPU 确实在满负荷画 UI |
| vdec 中断（硬解干活计数） | 0 | **+0（3 次采样，间隔 5~8s）** | 硬解一次都没动过 |
| 容器 CPU | 11% | 138%（启动峰值 262%） | — |
| webrtc 串流容器 CPU | — | 0.57% | 串流已不是瓶颈（30fps/1080/8M 生效） |

## 证据链

1. **抖音有硬解代码路径**：`libttmplayer.so` 内含 `MediaCodec`(7 处)、`AMediaCodec`(1 处)、`OMX.`(3 处)；`libttffmpeg.so` 是它自带的纯软解兜底库。
2. **系统会优先给它硬解**：`/vendor/etc/media_codecs.xml` 里 `OMX.meson.h264.decoder` 排在 H264 解码第一位，框架按 MIME 查询时会先选中我们的硬解组件（mctest 已验证过自动选中）。
3. **但现在硬解用不了**：宿主 `/proc/interrupts` 里 vdec 计数恒定不动，全机没有任何进程持有 `/dev/video0` —— VDEC 固件卡死中（昨天验证脚本超时被杀导致的）。

## 为什么"之前占用没这么高"

| 时间 | VDEC 状态 | 抖音解码路径 | CPU |
|---|---|---|---|
| 之前 | 正常 | MediaCodec → OMX.meson 硬解 | 低（你看到的） |
| 现在 | **卡死** | 硬解创建失败 → 回退 libttffmpeg 软解 | **高（你现在看到的）** |

串流那部分反而是反过来的：已经从 60fps/1280/16M 降到 30fps/1080/8M，串流软编码从 361% 降到 0.57%。所以现在剩下的 CPU 大头就是**抖音的软解**。

## 恢复方式

VDEC 需要重启宿主才能复位（自愈脚本里已加 `modprobe meson-vdec` 兜底，开机一分钟内自动完成：注入 OMX 插件 → chmod /dev/video0 → 重启 mediaserver）。

- **不要**尝试在线 `rmmod meson_vdec`：`amvdec_ports` 属于闭源 amports 家族，模块引用计数 3，强拆有整机死锁风险（无看门狗，需物理断电）。
- 重启后验证方法：抖音播放时再看 `/proc/interrupts` 的 vdec 计数，若持续上涨即硬解生效，同时抖音 CPU 应明显下降。

# 重启后复测（00:22 重启，00:27 上线，耗时 267 秒）

## 恢复验收：全部通过

| 项目 | 重启前 | 重启后 | 结论 |
|---|---|---|---|
| `meson_vdec` 模块引用计数 | **3（卡死残留）** | **0（干净）** | 固件卡死解除 |
| `/dev/video0` 权限 | 666（但固件死） | 666 | 正常 |
| mctest 720p×100 帧 | 取不到帧 | **真实帧 100/100，894ms，rc=0** | 硬解恢复 |
| 宿主 vdec 中断 | +0 | **0 → 99** | 硬件在真解码 |
| 框架是否自动选中 meson | — | 是（未强制组件名） | App 可直接受益 |
| GPU 直通 | mesa / Mali-G52 | mesa / Mali-G52 | 保留 |
| Vulkan | Mali-G52 (Panfrost) | Mali-G52 (Panfrost) | 保留 |
| swap 占用 | 1057 MB | **131 MB** | 内存压力解除 |
| webrtc 串流容器 CPU | 0.57% | 0.03~0.12% | 保持低位 |

所以插件无需重新注入（md5 一致），mediaserver 启动时就已能看到 meson 组件。
